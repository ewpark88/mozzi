## ADR-001 자체 경량 결정론적 물리 (flame_forge2d 미사용)
- 날짜: 2026-09-28 · 상태: 채택
- 맥락: GDD §10 은 flame_forge2d 를 명시했지만, 밸런스·페이싱은 공식 `d = v²/g × …` 기반이고 데일리 챌린지(고정 시드)·리플레이·헤드리스 테스트가 필요하다.

- 결과: 공식과 실측 거리 보정 쉬움, 결정론 보장, 테스트 용이. 대신 복잡한 강체 충돌은 직접 만들어야 한다(게임 특성상 불필요).

## ADR-008 페이싱 시뮬 규칙 명세 (밸런스 시트 「진행 시뮬」 역산)
- 날짜: 2026-09-28 · 상태: 채택
- 맥락: 시트의 진행 시뮬은 결과값만 있고 규칙이 없었다. P1 에서 규칙을 역산해 300판 × 3시나리오 전 셀 일치를 확인했다.
- 결정:
  - 판당 씨앗 = `d × coin_per_m × (1 + coin·Lv) × 광고배율`, 시뮬 내부는 소수 누적(표시만 반올림)
  - 판 종료마다 “씨앗 1개당 판당 씨앗 증가량” 최대 업그레이드를 반복 구매, 최선 항목이 부족하면 그 판 구매 종료(차선 구매 없음)
  - 비용 반올림은 사사오입(Excel ROUND = Dart `round()`). 시트 원본 시뮬은 은행가 반올림이었으나 결과 차이 없음(.5 비용은 고무줄 Lv1, 바운스 Lv2 뿐)
  - 광고 30% 시나리오 = 매판 ×1.3 기대값 모델
  - 기준 구현 2개: `tool/balance/pacing_sim.py`(시트 생성기), `lib/domain/balance/pacing_simulator.dart`(게임). 둘 다 fixture 로 시트와 비교
- 결과: 설정값을 바꾸면 스크립트로 시트를 재생성할 수 있고, 게임 코드와 시트가 어긋나면 테스트가 실패한다.
- 게임 내 실제 지갑은 정수(판마다 번 씨앗을 반올림해 적립) — 소수 누적은 시뮬 전용.

## ADR-009 2.5D 코드 렌더링, 외부 에셋 없음 (GDD 2026-09-28 개정 반영)
- 날짜: 2026-09-28 · 상태: 채택
- 맥락: GDD 가 “2D 게임플레이 + 2.5D 입체 셰이딩, 외주·유료 에셋 없이 전부 코드로 제작, Rive 대신 Flame 코드 애니메이션”으로 개정됨.
- 결정: 캐릭터·오브젝트·배경·이펙트를 `lib/game/render/`(파츠 레이어 + 셰이딩) 와 `shaders/*.frag`(FragmentShader)로 만든다. Rive 미사용. 효과음은 코드 합성, 폰트는 OFL(Jua, Gowun Dodum 등).
- 결과: 에셋 비용 0, 스킨은 색·재질 값만 추가. 대신 렌더링 품질 반복 개선과 저사양 성능(캐싱, 저사양 모드) 작업이 필요하다 → DEV_PLAN P2·P7 반영.

## ADR-012 비행 물리 = 미터 시뮬(공식 일치) + 샘플 체감 배율
- 날짜: 2026-09-28 · 상태: 채택 (사용자: “1번 2번 모두 고려”)
- 결정:
  1. 시뮬은 미터·실제 중력(9.8)으로 계산 — 공기역학은 유효 중력 `g/배율`, 바운스는 반발 계수 `e = √(b/(1+b))`,
     튐 꼬리는 일정 감속 미끄러짐. 조작 없는 45° 발사 거리 = GDD §5 공식 d (125개 레벨 조합 ±0.1% 확인).
  2. 체감은 2.5D 샘플 기준: 시간 배율 `sim_time_scale = 샘플g·v0 / (샘플v·g) ≈ 1.648`, 카메라 `cam_base_px_per_m = 샘플v / (v0·배율) ≈ 52.6`.
     Lv0 에서 화면 속 속도·중력이 샘플(V100 1300px/s, GRAV 1400px/s²)과 같다. 두 값은 시트 「설정」 수식.
- 결과: 페이싱(시트)과 실제 비행이 어긋나지 않고, 손맛은 샘플과 같다. 샘플의 공기저항(6%/s)은 공식 일치를 위해 넣지 않음.

## ADR-013 정확도 게이지 배율 해석 (G11·Q6)
- 날짜: 2026-09-28 · 상태: 채택 (사용자 “진행해” — 미결정 항목은 GDD 우선 원칙으로 결정, 시트 값으로 언제든 변경)
- 맥락: GDD 표는 GREAT ×1.03~1.13 인데 샘플 보간은 최대 1.097. GDD 는 “발사 속도는 힘에 비례”라면서 “최대 거리 ×1.27(=1.1×1.15)”이라고 해 속도·거리 기준이 섞여 있음.
- 결정:
  1. 판정 배율은 각 구간의 바깥 경계 = 최소, 안쪽 경계 = 최대로 선형 보간 → GREAT 이 GDD 대로 1.13 까지 도달 (구간 경계에서 배율 연속).
  2. 발사 속도 배율 = (힘 × 판정 배율)^`gauge_speed_exponent`, 기본 0.5 → 힘×배율이 **거리**에 그대로 곱해짐 (GDD 의 “최대 거리 ×1.27” 을 정확히 만족). 1.0 으로 바꾸면 샘플처럼 속도에 곱함.
  3. 페이싱 기준(시트 공식 d) = 힘 100% · 배율 1.0 (GOOD 과 GREAT 사이) 발사.
- 결과: GDD 수치가 그대로 성립. GDD 문장 “발사 속도는 힘에 비례”는 “거리가 힘에 비례”로 고치는 것을 제안(G12).

## ADR-014 비행 조작 3종의 물리와 공식 보정
- 날짜: 2026-09-28 · 상태: 채택
- 결정:
  - 입력은 GDD 대로 부스터 = 탭, 볼 부풀리기 = 홀드, 급강하 = 아래 스와이프 (샘플은 “누르고 있는 동안 부스터” 였으나 GDD 우선).
  - 부스터 연료 = 거리 예산 `20·Lv^1.3 × 바운스 배율`. 분사 중 수평 **이동량**을 더해(속도 아님) 공중에서 다 쓰면 공식 d 와 정확히 같다 → 페이싱 시트의 “부스터 포함 거리”가 실제 플레이에서도 성립 (24조합 ±0.2%).
  - 볼 부풀리기·급강하는 공식 밖 숙련 보너스(GDD §5: 페이싱에 조작 미반영). 급강하의 바운스 오브젝트 효과는 P5.
- 결과: 부스터를 안 쓰거나 늦게 쓰면 공식보다 덜 가고, 잘 쓰면 공식만큼 간다.

## ADR-015 오브젝트·청크·별 판정 구조
- 날짜: 2026-09-28 · 상태: 채택
- 결정:
  - 한 판 = `RunSession`(domain/run): 비행 시뮬 + `ObjectField`(청크 캐시·사용 기록) + `ObjectInteractor`(효과) + `RunStats` + 골. 게임과 헤드리스 테스트가 같은 경로.
  - 배치는 100m 청크 결정론 `(런 시드, 청크 번호)`. 간격 = max(5m, 거리×0.08), 크기·높이는 거리 배율 s 로 키운다 — 궤적이 거리에 비례해 커지므로 고정 크기면 멀리서 못 맞힌다.
  - 효과는 순간 속도 변경(튕김·상승·가속·감속) + 영역(상승기류 가속) + 시간 효과(우산 강제 활공). 트램폴린은 중력 포함 다음 스텝 예측으로 땅보다 먼저 튕긴다.
  - 콤보: 장애물 외 적중마다 +1, 착지(접지) 시 0. 씨앗 값 = 1.1^콤보 (먹은 씨앗에 적용, 거리 씨앗과 별도 — 보상 합산은 P6).
  - 미션은 타입 문자열 + 파라미터 맵(GDD 미션 타입 15종 모두 판정기 구현). 오브젝트 적중은 문자열 키로 세어 월드 4~6 미션도 같은 판정기로.
  - 수치(효과·배치·월드 비중)는 시트 「오브젝트」. GDD 에 수치가 없어 샘플·설계값 (GDD 제안 G17).
- 결과: 페이싱 공식은 조작·오브젝트 없는 기준 그대로(오브젝트 없는 RunSession = 공식 거리 테스트), 오브젝트는 숙련 보너스.

## ADR-016 RC 키·스테이지 데이터는 GDD §10·§4 이름을 따른다
- 날짜: 2026-09-29 · 상태: 채택 (사용자 선택)
- 맥락: 사용자가 GDD §10 비행 조작 RC 키와 §4 스테이지 데이터 형식을 확정했는데, 코드·시트 이름(`inflate_drag_per_sec`, `gesture_swipe_px`, `stages[].stage/target_m`)과 달랐다.
- 결정:
  - 시트·JSON·도메인 키를 GDD 이름으로 바꾼다: `inflate_decel_per_sec`, `gesture_swipe_min_px`. GDD 에만 있던 `boost_lv0_fuel_sec`(0), `boost_cut_on_land`(true), `gesture_tap_max_sec`(0.18)을 시트에 추가하고 코드가 읽는다 (Lv0 연료, 착지 시 분사 소멸, 탭 판정).
  - 스테이지는 `stage_table` = `{"stages": [{"id": "3-3", "world", "goal", "boss", "star3", "star3_text"}]}`. 번들 JSON 도 같은 형식, `id` 와 `world` 가 어긋나면 로드 실패.
  - GDD 목록에 없는 급강하 키 3개와 `star3_text` 는 유지하고 GDD 추가를 제안(G19·G20). Dart 필드명(`targetM`, `gestureSwipePx`)은 그대로.
- 결과: RC 콘솔에 GDD 목록 그대로 키를 만들면 코드가 읽는다. 값은 바뀌지 않았다 (테스트·판수 재현 동일).

## ADR-017 메타 루프: 판 보상 합산, 보스 규칙 해석·수치, 세이브 v2
- 날짜: 2026-09-29 · 상태: 채택 (P6, 사용자 승인한 세부 계획)
- 맥락: GDD 는 “거리 씨앗과 먹은 씨앗은 별도 계산”, 보스 1-5·3-5 의 규칙만 있고 수치가 없다. 2-5 는 T=16초만 있다.
- 결정:
  1. **판 씨앗** = `seedsForDistance(거리)`(페이싱 공식 그대로) + `roundHalfUp(먹은 씨앗 값 × 볼주머니 배율)`. 결과 화면 광고는 합계 × `ad_reward_multiplier`(2, 시트 「설정」 71행). 실패해도 지급.
  2. **보스 시간은 실제 초**(시뮬 초 ÷ `sim_time_scale`). 보스에게 지면 그 자리에서 판이 끝난다(`FlightSimulator.halt`).
     - 1-5 고양이: 발사 2초 뒤 출발, 발사 후 `boss_1_5_cat_time_sec`(6초)에 500m 도달하는 등속. 모찌 위치에 닿으면 실패. 1-5 클리어 수준(시뮬 13판 레벨) PERFECT+부스터 3.6초 승, 부스터 없이 7.9초 패.
     - 2-5 비둘기 대장: 등속으로 T 에 골인. 코스는 비둘기 비중 ×1.5, 분수 2~3개 고정 배치(`CourseTweak`), 나뭇가지는 공원 비율 그대로.
     - 3-5 까마귀 대장: 비행 중 실제 초당 `boss_3_5_steal_per_sec`(0.019) + 까마귀 충돌마다 `boss_3_5_crow_hit_meter`(0.1). 3-5 클리어 수준(29판) PERFECT+부스터 31.6초 → 약 60%.
     - 완화: 연속 실패 3판마다 5%(최대 15%), 클리어 시 0. 고양이·대장은 시간 ×(1+완화), 까마귀는 게이지 ×(1−완화).

## ADR-018 2.5D 렌더링은 Canvas 그라데이션 + Picture 캐시 (FragmentShader 없음)
- 날짜: 2026-09-29 · 상태: 채택 (P7, 사용자 승인)
- 맥락: DEV_PLAN P7 은 면 그라데이션·림라이트·스페큘러를 FragmentShader 로, Canvas 를 대체 경로로 계획했다. 시각 기준 샘플(`모찌 런처 2.5D.html`)은 전부 Canvas 방사형 그라데이션(`radial`·`softSpot`)으로 2.5D 질감을 낸다.
- 결정:
  - 셰이딩 7단계를 Canvas `Gradient.radial`(초점 원 포함)로 샘플 그대로 옮긴다 (`game/render/shade.dart`, `mochi/`). 셰이더 컴파일·로드 실패 위험과 대체 경로 이중 유지를 없앤다.
  - 성능: 그라데이션이 많은 몸은 (자세·볼 크기 0.05 단계·림 색·저사양) 별로 `Picture` 캐시(`MochiBodyCache`, 최대 24개), 얼굴은 매 프레임 가볍게.
  - 저사양 모드 = 털 스트로크·배경 대기 안개·해 글로우 끔. 기본값 RC `render_low_spec`(시트 「설정」 74행).
  - 색은 `game/render/palette.dart` 한 곳 (game·ui 는 app 을 import 할 수 없어 `app/theme` 대신).
  - 표정 9종은 그리기·갤러리까지. 언제 어떤 표정인지는 P8 상태 머신 (`domain/character/MochiExpression`).
  - DoD “셰이더 로드 실패 시 대체 경로 테스트” → “저사양 경로 테스트”.
- 결과: 테스트 환경에서도 같은 경로로 그려져 표정 9종 × 자세 × 저사양을 전부 검증. GDD §10 캐릭터 렌더링 문구 수정 제안 G24.

## ADR-019 효과음 코드 합성 + flutter_soloud, OFL 폰트, 온보딩 범위
- 날짜: 2026-09-29 · 상태: 채택 (P8, 사용자 승인) · Q4 해결
- 결정:
  1. **효과음**: 샘플의 tone·noise·squeak·boost 를 순수 Dart PCM 합성(`core/audio/pcm_synth.dart`, 22.05kHz 16bit 모노 WAV, 노이즈 시드 고정 → 결정론)으로 옮기고, 앱 시작 시 한 번 합성해 메모리로 불러온다(`game/audio/sfx_bank.dart`).
     재생은 **flutter_soloud**(^4.1.7): 저지연, 루프 재생 중 재생 속도(음높이)·음량 조절 → 고무 소리 음높이 상승·콤보 음계 상승을 재생 속도로 처리. audioplayers 보다 지연이 작고 루프 음높이 조절이 부드럽다. 초기화 실패 시 로그 후 무음 진행. 인터페이스 `domain/services/SoundService`, 테스트는 `SilentSoundService`.
  2. **폰트**: OFL 인 Jua(제목·버튼·HUD 굵은 글자)·Gowun Dodum(본문)을 `assets/fonts/` 에 라이선스와 함께 번들 (`ui/app_theme.dart`).
  3. **표정**: `domain/character/ExpressionMachine` 이 게임 이벤트로 표정·지속 시간을 정하고, `game/RunPresenter` 가 표정·효과음·파티클·진동을 한곳에서 연결 (MozziGame 은 진행만).
  4. **온보딩**(GDD §9) 은 판 수로 단계를 정한다(`domain/onboarding/Onboarding`). 첫 무료 업그레이드 = 1판 뒤 **부스터 Lv1** (Lv0 은 연료가 없어 2판에 부스터를 가르칠 수 없음, `onboardingStep` 1 = 받음). 1판 트램폴린은 조작 없이 날린 기대 거리 × 0.8 에 고정 배치.
     시스템이 아직 없는 단계는 해당 Phase 로: 3판 황금 씨앗 확정 → P14, 5판 이후 전면 광고 → P9, 월드 1 클리어 캐릭터 교체 안내 → P12.
- 결과: 에셋 없이 소리·폰트·표정이 들어가고, 합성음은 테스트로 바이트 단위 검증. GDD 제안 G26(무료 업그레이드 = 부스터).
